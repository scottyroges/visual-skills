# Plain-Language Guide

Use this guide for every sentence written for the reader. This includes page titles, summaries,
labels, prose, diagram text, code annotations, quiz content, live grading, and completion messages.
Treat each generated page and each live reply as a new response.

Keep source code, commands, file paths, fixed field names, exact product names, and quotations
unchanged. If readers need help with one, explain it in the same sentence as its first use.

## Reader

Write for a smart reader who has no background in the topic. Assume general English and basic
computer use. Assume nothing else.

## Words

- Use the plainest accurate word.
- Use a technical term only when it is the subject or will help the reader later.
- Explain the idea first, then add its technical name when useful. For example: “Stored results
  are cleared after an edit (cache invalidation).”
- Keep the definition in the same sentence as the first use. Do not place it in the next sentence
  or bullet. Cut the term if a short definition does not fit.
- Use only plain words in titles and short labels. Introduce technical names in body text, where
  there is room to define them.
- Spell out every acronym on first use in each page or live reply. Check the expansion against the
  source. If it contains another acronym, spell out both.
- Spelling out an acronym does not define it. Also explain what the named thing does.
- Do not write “as you know,” “simply,” “just,” “obviously,” or “of course.”

## Directness

- Start with the answer. Put context after it.
- Do not restate the reader's question.
- Cut filler and softening words, including “essentially,” “fundamentally,” “it's worth noting,”
  “in order to,” “very,” “quite,” and “really.”
- Do not end with a summary of points the reader has already read.
- Do not use metaphors, imagery, scene-setting, rhetorical questions, or rhythmic flourishes.
- Explain what something does before giving its technical name.

## Page Shape

- Keep paragraphs to four sentences or fewer.
- Put lists of three or more items in bullets.
- Use short headings when the response covers more than two topics.
- Give each sentence one idea.
- Aim for fewer than 20 words per sentence. Vary sentence length enough to keep the writing natural.

## Final Check

Before sending or rendering, reread every user-facing field. Cut any word the reader may need to
look up. Cut any sentence that exists only to sound good.
